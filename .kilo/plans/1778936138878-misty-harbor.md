## Remaining Runtime Error — AuthService DI Resolution ❌

### Error
```
Nest can't resolve dependencies of the AuthService (?, JwtService)
Argument at index [0] is undefined at runtime
```

### Root Cause Analysis

**Three files involved:**

| File | Problem |
|------|---------|
| `domain/auth/i-user.repository.ts:3` | `IUserRepository` is a pure TypeScript `interface` — **no runtime token** |
| `auth.module.ts:27` | Provider uses string token: `provide: 'IUserRepository'` |
| `auth.service.ts:11` | Constructor uses `private readonly userRepository: IUserRepository` — **no `@Inject()` decorator** |

Since `IUserRepository` is an interface, it's erased at transpilation. NestJS receives `undefined` as the injection token. The module registers the provider under the string `'IUserRepository'`, but the service doesn't tell NestJS to look for that string token.

### Comparison with Working Modules

**ChildrenModule / ServicesModule (WORKING):**
```
i-child-repository.interface.ts:     export const IChildRepository = Symbol('IChildRepository')
children.module.ts:                  provide: IChildRepository,         // Symbol used as token
children.service.ts:                 @Inject(IChildRepository)          // Symbol matched with @Inject
```

**AuthModule (BROKEN):**
```
i-user.repository.ts:                export interface IUserRepository   // ONLY interface, no Symbol
auth.module.ts:                      provide: 'IUserRepository',        // String token
auth.service.ts:                     NO @Inject()                       // Nothing to match the string token
```

### Recommended Fix (align with codebase convention)

**File 1: `domain/auth/i-user.repository.ts`**
Add a Symbol token alongside the interface:
```typescript
export const IUserRepository = Symbol('IUserRepository');

export interface IUserRepository {
  findByEmail(email: string): Promise<User | null>;
  findById(id: string): Promise<User | null>;
  create(user: Omit<User, 'id' | 'createdAt' | 'updatedAt'>): Promise<User>;
  update(id: string, updates: Partial<User>): Promise<User>;
}
```

**File 2: `auth.module.ts`** (line 27)
Change `provide: 'IUserRepository'` → `provide: IUserRepository` (use the Symbol)

**File 3: `application/auth/auth.service.ts`** (line 3 + line 11)
- Change `import type { IUserRepository }` → `import { Inject } from '@nestjs/common'` + `import { IUserRepository }` (remove `type`)
- Add `@Inject(IUserRepository)` decorator to constructor parameter

### Why `import type` must change to `import`
NestJS uses the class/Symbol as a runtime DI token. With `import type`, the Symbol is erased at compile time. The token would be `undefined` at runtime — same error. Must use `import { IUserRepository }` (value import).
